# Workflow ролей

Документ описывает рабочие сценарии трех ролей в приложении digital-showcase: Админа, Владельца и Клиента. Описание основано на текущих frontend- и backend-маршрутах проекта.

## 1. Общая модель приложения

Приложение состоит из трех пользовательских зон:

- публичная витрина магазина: `/m/:storeSlug`;
- личный кабинет владельца: `/dashboard`;
- административная панель: `/admin`.

Роли в системе:

- `ADMIN` - управляет владельцами, магазинами, подписками, активностью магазинов и доступом к AI-заполнению формы товара;
- `OWNER` - управляет своими магазинами, товарами, изображениями, реквизитами и публичной ссылкой;
- Клиент - не авторизуется, просматривает публичную витрину и карточки товаров.

Авторизованные зоны защищены JWT-токеном:

- админские маршруты доступны только пользователю с ролью `ADMIN`;
- маршруты владельца доступны только пользователю с ролью `OWNER`;
- клиентские публичные маршруты доступны без авторизации, но только для активных магазинов с действующей подпиской.

## 2. Workflow Админа

### 2.1. Вход в систему

1. Админ открывает страницу входа: `/login`.
2. Вводит учетные данные.
3. После успешной авторизации получает JWT-токен.
4. Переходит в административную панель: `/admin`.

Если пользователь не авторизован или имеет роль не `ADMIN`, доступ к `/admin` и вложенным админским страницам запрещается.

### 2.2. Главная админ-панель

Админ открывает `/admin` и видит основные разделы:

- Владельцы: `/admin/owners`;
- Магазины: `/admin/stores`.

Главная задача админа - создать владельца, создать для него магазин и управлять жизненным циклом магазина.

### 2.3. Управление владельцами

Страница: `/admin/owners`.

Админ может:

- просматривать список владельцев;
- создать нового владельца;
- изменить пароль владельца;
- удалить владельца через API, если такая операция используется в интерфейсе или внешней админской интеграции.

Создание владельца:

1. Админ открывает раздел владельцев.
2. Заполняет форму:
   - имя;
   - email;
   - телефон;
   - пароль.
3. Отправляет форму.
4. Backend создает пользователя с ролью `OWNER`.
5. Новый владелец появляется в списке.

Смена пароля владельца:

1. Админ находит владельца в списке.
2. Открывает меню действий владельца.
3. Выбирает действие смены пароля.
4. Вводит новый пароль.
5. Сохраняет изменения.
6. Владелец сможет войти с новым паролем.

Минимальные обязательные данные при создании владельца:

- `name`;
- `password`.

### 2.4. Управление магазинами

Страница: `/admin/stores`.

Админ может:

- просматривать список всех магазинов;
- создавать магазин для выбранного владельца;
- продлевать подписку магазина на 30 дней;
- архивировать магазин;
- восстанавливать магазин из архива;
- включать или отключать AI-заполнение формы товара;
- обновлять или удалять магазин через API.

Создание магазина:

1. Админ открывает раздел магазинов.
2. Выбирает владельца из списка.
3. Заполняет:
   - название магазина;
   - `slug` для публичной ссылки;
   - дату окончания подписки, если нужно.
4. Сохраняет форму.
5. Магазин создается активным по умолчанию.
6. Публичный адрес магазина формируется как `/m/:slug`.

Обязательные поля при создании магазина:

- `ownerId`;
- `name`;
- `slug`.

### 2.5. Управление подпиской

Подписка влияет на публичную доступность магазина.

Админ может нажать `+30 дней` для магазина. Backend:

1. Берет текущую дату окончания подписки, если она еще не истекла.
2. Если подписка уже истекла или даты нет, берет текущую дату.
3. Добавляет 30 дней.
4. Делает магазин активным.

Публичная витрина доступна клиентам только если:

- магазин активен: `isActive = 1`;
- подписка не истекла или дата окончания подписки не задана.

### 2.6. Архивация и восстановление магазина

Архивация:

1. Админ нажимает `Архивировать`.
2. Backend выставляет `isActive = 0`.
3. Магазин становится недоступен клиентам в публичной зоне.
4. Владелец видит статус магазина как архивный.

Восстановление:

1. Админ нажимает `Восстановить`.
2. Backend выставляет `isActive = 1`.
3. Если подписка действительна или не ограничена датой, публичная витрина снова доступна.

### 2.7. Управление AI-заполнением формы товара

Админ может включить или отключить AI-форму для конкретного магазина.

Если AI-форма включена:

- владелец может открыть AI-режим в форме товара;
- владелец может заполнить товар по текстовому описанию или голосовой записи.

Если AI-форма отключена:

- переключатель AI-режима в форме товара заблокирован;
- backend не разрешает создание AI-черновика для этого магазина.

## 3. Workflow Владельца

### 3.1. Вход в систему

1. Владелец открывает `/login`.
2. Вводит учетные данные, созданные админом.
3. После успешной авторизации получает JWT-токен.
4. Переходит в личный кабинет: `/dashboard`.

Если пользователь не авторизован или имеет роль не `OWNER`, доступ к кабинету владельца запрещается.

### 3.2. Выбор магазина

Страница: `/dashboard`.

После входа владелец видит список своих магазинов.

Для каждого магазина отображается:

- название;
- логотип, если указан;
- статус активности;
- публичная ссылка вида `/m/:slug`;
- дата создания;
- действия перехода к товарам и реквизитам.

Workflow:

1. Владелец открывает кабинет.
2. Выбирает нужный магазин.
3. Переходит на страницу магазина: `/dashboard/stores/:storeId`.
4. Если магазинов нет, видит сообщение, что магазин еще не создан.

Владелец может работать только с магазинами, которые принадлежат его учетной записи.

### 3.3. Управление товарами магазина

Страница: `/dashboard/stores/:storeId`.

Владелец видит:

- список товаров;
- статистику по товарам;
- поиск по названию;
- фильтр по статусу;
- фильтр по категории;
- сортировку по дате обновления или цене;
- действия просмотра публичной карточки и редактирования товара.

Статусы товара в кабинете владельца:

- опубликован - `isVisible = 1` и товар не имеет статуса `NOT_AVAILABLE`;
- черновик - `isVisible = 0`;
- архив - `status = NOT_AVAILABLE`.

Доступные сценарии:

- открыть публичную карточку товара;
- создать новый товар;
- отредактировать существующий товар;
- удалить товар через API;
- загрузить, удалить и переупорядочить изображения товара.

### 3.4. Создание товара

Страница: `/dashboard/stores/:storeId/products/new`.

Workflow обычного создания:

1. Владелец выбирает магазин.
2. Нажимает добавление товара.
3. Заполняет форму:
   - название;
   - описание;
   - цену или режим `Уточнить у продавца`;
   - категорию;
   - статус;
   - видимость;
   - варианты товара;
   - изображения.
4. Добавляет комбинации товара:
   - цвет;
   - HEX-цвет;
   - размер;
   - цена конкретной комбинации.
5. Загружает изображения товара.
6. Выбирает изображение-превью.
7. Сохраняет товар.
8. Backend создает товар, сохраняет варианты, размеры, цвета и изображения.
9. Владелец возвращается на страницу магазина.

Обязательное поле товара:

- `title`.

### 3.5. Создание товара через AI-черновик

AI-режим доступен только если админ включил `aiFormEnabled` для магазина.

Workflow текстового AI-заполнения:

1. Владелец открывает форму нового или существующего товара.
2. Включает AI-режим.
3. Выбирает текстовый ввод.
4. Описывает товар свободным текстом.
5. Нажимает заполнение формы.
6. Backend возвращает черновик товара.
7. Форма заполняется значениями из черновика.
8. Владелец проверяет и редактирует поля.
9. Сохраняет товар.

Workflow голосового AI-заполнения:

1. Владелец включает AI-режим.
2. Выбирает голосовой ввод.
3. Записывает описание товара через микрофон.
4. Отправляет запись.
5. Backend получает аудиофайл и формирует черновик.
6. Владелец проверяет заполненную форму.
7. Сохраняет товар.

Форма подсказывает владельцу, какие данные стоит проговорить:

- что это за товар и как он называется;
- какие цвета доступны;
- какие размеры есть у каждого цвета;
- сколько стоит товар или отдельные комбинации;
- к какой категории относится товар.

Если AI-форма отключена:

- переключатель AI-режима недоступен;
- backend вернет ошибку доступа при попытке создать AI-черновик.

### 3.6. Редактирование товара

Страница: `/dashboard/stores/:storeId/products/:id/edit`.

Workflow:

1. Владелец открывает товар на редактирование.
2. Backend загружает данные товара, изображения, размеры, цвета и варианты.
3. Владелец меняет нужные поля.
4. Может добавить новые изображения.
5. Может удалить существующие изображения.
6. Может выбрать новое изображение-превью.
7. Может изменить порядок изображений.
8. Сохраняет изменения.
9. Backend обновляет товар и связанные данные.
10. Владелец возвращается на страницу магазина.

### 3.7. Управление реквизитами магазина

Страница: `/dashboard/stores/:storeId/settings`.

Владелец может редактировать:

- название магазина;
- описание;
- адрес;
- телефон;
- WhatsApp;
- Telegram;
- URL логотипа;
- URL обложки.

Workflow:

1. Владелец открывает настройки магазина.
2. Изменяет реквизиты.
3. Сохраняет форму.
4. Данные обновляются в магазине.
5. Изменения отражаются на публичной витрине и в карточке товара.

Владелец не управляет:

- владельцем магазина;
- `slug`;
- активностью магазина;
- датой окончания подписки;
- включением AI-формы.

Эти параметры находятся в зоне ответственности админа.

### 3.8. Работа с публичной ссылкой

Владелец видит публичную ссылку магазина:

```text
/m/:storeSlug
```

Он может:

- открыть публичную витрину;
- скопировать ссылку;
- передать ссылку клиентам.

Публичная ссылка работает для клиентов только при активном магазине и действующей подписке.

## 4. Workflow Клиента

### 4.1. Открытие публичной витрины

Страница: `/m/:storeSlug`.

Клиент не проходит авторизацию.

Workflow:

1. Клиент получает ссылку на магазин.
2. Открывает `/m/:storeSlug`.
3. Backend ищет магазин по `slug`.
4. Backend проверяет активность и подписку магазина.
5. Если магазин доступен, клиент видит витрину.
6. Если магазин не найден, архивирован или подписка истекла, клиент видит сообщение о недоступности.

### 4.2. Просмотр каталога

На витрине клиент видит:

- название магазина;
- описание магазина;
- список видимых товаров;
- фильтры;
- сортировку.

Клиент может фильтровать товары по:

- поисковой строке в названии;
- категории;
- размеру;
- цвету.

Клиент может сортировать товары:

- сначала новые;
- по цене от низкой к высокой;
- по цене от высокой к низкой.

Публичный каталог показывает только товары с `isVisible = 1`.

### 4.3. Открытие карточки товара

Страница: `/m/:storeSlug/p/:productId`.

Workflow:

1. Клиент выбирает товар на витрине.
2. Открывает карточку товара.
3. Backend проверяет магазин и доступность подписки.
4. Backend загружает только публично видимый товар.
5. Клиент видит подробности товара.

В карточке товара отображается:

- название;
- изображения;
- описание;
- цена или текст цены;
- цвета;
- размеры;
- варианты цвет + размер + цена;
- статус наличия;
- контактный блок магазина.

### 4.4. Выбор варианта товара

Если у товара есть варианты, клиент может выбрать:

- цвет;
- размер.

Логика выбора:

1. Клиент выбирает цвет или размер первым.
2. Второй список вариантов ограничивается совместимыми комбинациями.
3. Если ранее выбранная комбинация становится невозможной, несовместимый выбор сбрасывается.
4. Цена обновляется по выбранному варианту, если у варианта указана отдельная цена.
5. Клиент может сбросить выбор.

Если вариантов нет, карточка показывает простые списки размеров и цветов.

### 4.5. Связь с магазином

Клиент нажимает кнопку связи с магазином.

Приоритет канала связи:

1. WhatsApp, если указан;
2. Telegram, если указан;
3. телефон, если указан.

Формирование ссылки:

- WhatsApp преобразуется в ссылку `https://wa.me/...`;
- Telegram преобразуется в `https://t.me/...`, если указан username без полного URL;
- телефон преобразуется в `tel:...`.

Если контакты не заполнены, ссылка фактически не ведет к внешнему каналу.

## 5. Сквозные состояния и правила доступа

### 5.1. Магазин

Основные состояния магазина:

- активен: `isActive = 1`;
- архивирован: `isActive = 0`;
- AI-форма включена: `aiFormEnabled = 1`;
- AI-форма отключена: `aiFormEnabled = 0`;
- подписка действует: `subscriptionEndsAt` не задана или дата в будущем;
- подписка истекла: `subscriptionEndsAt` в прошлом.

Публичная доступность магазина:

```text
isActive = 1 AND (subscriptionEndsAt is null OR subscriptionEndsAt >= now)
```

### 5.2. Товар

Основные состояния товара:

- доступен: `AVAILABLE`;
- нет в наличии: `NOT_AVAILABLE`;
- уточнить в магазине: `CHECK_IN_STORE`;
- видимый на витрине: `isVisible = 1`;
- скрытый черновик: `isVisible = 0`.

Публичная доступность товара:

```text
product.storeId belongs to public store AND product.isVisible = 1
```

### 5.3. Изображения товара

Владелец может:

- загрузить несколько изображений;
- выбрать превью;
- удалить изображение;
- изменить порядок изображений.

Порядок изображений хранится через `sortOrder`. Первое изображение используется как главное в каталоге и карточке.

### 5.4. Варианты товара

Варианты товара описывают конкретные комбинации:

- цвет;
- HEX-цвет;
- размер;
- цена.

При сохранении вариантов backend также обновляет производные списки:

- уникальные размеры;
- уникальные цвета.

Эти списки используются в фильтрах каталога и в карточке товара.

## 6. Типовой сквозной сценарий от админа до клиента

1. Админ входит в `/admin`.
2. Админ создает владельца.
3. Админ создает магазин для владельца.
4. Админ задает `slug` и дату подписки.
5. При необходимости админ включает AI-форму для магазина.
6. Владелец входит в `/dashboard`.
7. Владелец выбирает созданный магазин.
8. Владелец заполняет реквизиты магазина.
9. Владелец создает товары вручную или через AI-черновик.
10. Владелец загружает изображения и варианты товара.
11. Владелец копирует публичную ссылку `/m/:storeSlug`.
12. Клиент открывает публичную витрину.
13. Клиент фильтрует каталог и открывает карточку товара.
14. Клиент выбирает вариант товара.
15. Клиент связывается с магазином через WhatsApp, Telegram или телефон.
