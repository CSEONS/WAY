# План: сделать сервис продаваемым и простым

Составлено 26.09.2026 по результатам разбора всего проекта (backend, frontend, инфраструктура). На момент разбора типы в обоих проектах проверяются без ошибок, 3 теста backend проходят.

Основа хорошая: много магазинов на одной установке, AI-черновики, фоновое сохранение товара, OG-превью для мессенджеров. Продавать мешают:

- нет единого набора компонентов, поэтому каждое изменение интерфейса дорогое;
- данные хранятся ненадёжно;
- интерфейс слишком сложный для владельца без технических навыков;
- нет инструментов, чтобы продавать и вести клиентов.

Модель — из [MOTIVATION.md](MOTIVATION.md): сервис по ежемесячной подписке на одном домене (`waytuk.ru/m/магазин`), а не продажа копий кода.

## Этап 1. Единые стили и UI-kit — делаем первым

Все следующие этапы (упрощение кабинета, новая витрина, лендинг, админка) — это переделка интерфейса. Если сначала собрать набор общих компонентов, новые экраны собираются из готовых деталей, а не из новых сотен строк CSS.

### Что сейчас

- Основа есть: токены отступов, скруглений и цветов в `:root` и правила в [STYLE_GUIDE.md](../frontend/src/styles/STYLE_GUIDE.md).
- Весь CSS лежит в одном [global.css](../frontend/src/styles/global.css) на 3245 строк.
- Около 490 строк секции «Legacy structural surfaces» стилизуют голые теги (`article`, `form`, `section > form`, `[role="dialog"]`) ради шести страниц. Плюс глобальное `svg { width: 20px }`. Такие правила протекают в любой новый компонент.
- Компонентов почти нет:
  - кнопки существуют только как CSS-классы (11 разных в разметке);
  - модальные окна размечены вручную в 8 файлах, `ConfirmModal` остальные не используют.
- Две библиотеки иконок: hugeicons (103 использования) и lucide (9 файлов). Размер и толщина иконки каждый раз пишутся руками: `size={16} strokeWidth={1.8}` встречается 41 раз, всего 8 разных сочетаний.
- 17 разных размеров шрифта без шкалы: от 11 до 26px плюс 5 `clamp`.
- Пять видов «чипов» (`chip`, `variant-size-chip`, `variant-color-chip`, `variant-price-chip`, `variant-ask-chip`) плюс отдельный `segmented`.
- Свой `Select`, а рядом нативный `<select>` в `BulkProductCreator.tsx` (с тех пор переписан: [components/bulk](../frontend/src/components/bulk/)).
- Поля ввода набраны шрифтом 15px, поэтому iOS Safari увеличивает страницу при фокусе. Нужно не меньше 16px.
- Вместо индикатора загрузки выводится просто текст «Загрузка...».
- В `:root` есть legacy-алиасы (`--text`, `--muted`, `--line` и др.), которые нигде не используются.

### Что сделать

1. **Токены** вынести в `styles/tokens.css`:
   - отступы, скругления и цвета оставить, неиспользуемые алиасы удалить;
   - добавить шкалу шрифтов (`--font-size-xs … --font-size-2xl`, 5–6 значений вместо 17), начертания и межстрочные интервалы;
   - добавить высоты контролов `--control-sm/md/lg` (для пальца минимум 44–48px); шрифт полей ввода — 16px;
   - добавить шкалу z-index и длительности анимаций.
2. **Компоненты в `frontend/src/ui/`**, у каждого свой CSS Module (Vite поддерживает их без новых зависимостей):

   | Компонент | Что заменяет |
   |---|---|
   | `Button`, `IconButton`: варианты primary/secondary/ghost/danger, размеры sm/md/lg, состояние `loading` | 11 CSS-классов `btn-*` |
   | `Icon`: обёртка над одной библиотекой с размерами sm/md/lg | hugeicons и lucide, ручные `size`/`strokeWidth` |
   | `Field` (подпись, подсказка, ошибка), `Input`, `Textarea`, `Select`, `Switch` | `<label>Название<input/></label>`, нативный `<select>` |
   | `Chip`, `ChipGroup`, `ColorSwatch`, `SegmentedControl` | 5 видов чипов |

### Готово, когда

- Нет стилей для голых тегов и секции legacy.
- Используется одна библиотека иконок.
- Нигде нет ручной разметки модального окна.

## Этап 2. Надёжность и безопасность — до первого чужого клиента

Если платящий магазин потеряет данные, репутации конец.

1. **Заменить sql.js на better-sqlite3 (режим WAL) и добавить миграции.**
   - Сейчас [db.ts:71](../backend/src/database/db.ts#L71) после *каждой* записи синхронно и неатомарно переписывает весь файл базы.
   - Каждый просмотр витрины ([publicController.ts:15](../backend/src/controllers/publicController.ts#L15)) — это запись. Значит, база переписывается целиком на каждом заходе покупателя.
   - Если процесс упадёт во время записи, файл базы повредится.
   - Изменения схемы вести через таблицу миграций, а не через `ALTER` внутри `initDatabase`.
2. **Ежедневные автоматические бэкапы** базы и `uploads` в S3-совместимое хранилище (Timeweb или Yandex Object Storage): хранить 30 дней, раз в месяц проверять восстановление.
3. **Безопасность:**
   - [server.ts:14](../backend/src/server.ts#L14) печатает `JWT_SECRET` в лог — убрать; убрать и запасное значение `"change_me"`;
   - ограничить число попыток входа (express-rate-limit), подключить helmet;
   - `client_max_body_size 620m` ([nginx.conf:17](../nginx/nginx.conf#L17)) уменьшить примерно до 60m;
   - пароль админа перезаписывается из `.env` при каждом старте ([db.ts:209](../backend/src/database/db.ts#L209)). README утверждает обратное и требует минимум 12 символов, а код — 6. Выбрать одно поведение.
4. **Проверка входных данных (zod) с понятными ошибками 400.** Короткий пароль, занятая почта и повторяющийся или кривой slug уже дают понятную 400 (этап 5); неверный статус товара и прочие поля — всё ещё 500. В продакшене пользователь видит только «Внутренняя ошибка сервера».
5. **Бизнес-баги:**
   - ~~магазин без даты подписки работает бесплатно бессрочно~~ — сделано в этапе 5: новый магазин без даты получает пробный период `TRIAL_DAYS`. Старые магазины без даты остаются бессрочными, пока админ не поставит дату;
   - при удалении владельца ([userService.ts:70](../backend/src/services/userService.ts#L70)) на диске остаются все фото его магазинов (записи в базе теперь удаляются каскадом — см. этап 4, — а файлы нет).
6. **Мониторинг:** ошибки 500 отправлять уведомлением в Telegram; `/api/health` проверять внешним сервисом мониторинга доступности.
7. **CI (GitHub Actions):** проверка типов, тесты, сборка. Добавить тесты на главное: владелец A не может менять магазин B; витрина с истёкшей подпиской не открывается.

## Позже: цена ИИ в рублях вместо токенов

Цены за миллион токенов в `.env` ничего не говорят владельцу сервиса. Теперь нужна одна цифра — курс, сколько рублей вы платите за $1 (сейчас — в «Настройках», см. ниже), а цены моделей записаны в [aiPrices.ts](../backend/src/services/aiPrices.ts) (по странице цен OpenAI на 17.10.2026 — обновлять, когда OpenAI их меняет). Каждая строка `ai_usage` помнит модель, поэтому смена модели посреди месяца не искажает цифры; старые строки считаются по модели, которая стоит сейчас. В карточке «ИИ-провайдер» — средняя цена карточки, средняя и самая дорогая цена превью за месяц, в плитке «ИИ за месяц» — общая сумма.

Цели: карточка — как можно дешевле, точности 60%+ достаточно; превью — читаемое и не дороже 3 ₽. Поэтому карточки по умолчанию заполняет `gpt-5.6-luna` (в ~20 раз дешевле `gpt-5.6`), превью рисует `gpt-image-2.5-flare` в качестве `medium` — около 2 ₽ за картинку по двум реальным запросам. Попутно: docker-compose теперь передаёт бэкенду `AI_PREVIEW_*`, а `OPENAI_MODEL` больше не подменяет модель по умолчанию. Тесты — [aiSpend.test.ts](../backend/test/aiSpend.test.ts).

## Позже: без лиц и живых существ на фото

На витрине нельзя показывать лица людей и животных. Каждое загруженное фото товара и логотип модель для карточек (Luna, копейки за фото) проверяет на лица — настоящие, на фото, рисунках, принтах и вышивке, игрушках, а также лица манекенов и кукол. Тело без лица не считается: руки, ноги, модель, обрезанная кадром по нос, человек со спины. Если лицо нашлось, фото попадает в таблицу `image_checks` со статусом «На проверке». Позже правило смягчено: фото остаётся на витрине, а владелец получает уведомление «Подозрение на нарушение правил площадки» с товаром и правилом; админ в «Проверка фото» (`/admin/moderation`) решает: «Показывать», «Скрыть фото» или «Снять товар» целиком (вкладка «Снятые товары» — вернуть). Сверху админки — «Фото на проверке: N». Владелец видит на своих фото метки «На проверке» / «Скрыто» и объяснение. Проверка идёт после ответа на загрузку (несколько секунд) и в лимит ИИ владельца не входит; если ИИ не настроен, фото не проверяются.

«Превью с ИИ»: в промпте — не рисовать людей, части тела, животных и лица манекенов (вещь на невидимом манекене или разложенной). Готовую картинку проверяет та же модель, но ничего не замазывает: владелец видит предупреждение, а если сделает такую картинку обложкой, при сохранении товар сразу уходит на проверку (форма передаёт находки вместе с фото, второй запрос к ИИ не нужен). В списке товаров владельца — «На проверке» / «Фото скрыто». Превью рисуется в фоне: после «Нарисовать» окно само сворачивается с уведомлением «будет готово в течение минуты», владелец заполняет товар дальше, по готовности — уведомление и кнопка «Превью готово — посмотреть» ([usePreviewDrawing.ts](../frontend/src/components/product-form/usePreviewDrawing.ts)).

Модерацию пока ведёт админ; API — отдельный (`/api/moderation`, проверка `moderatorOnly`), чтобы позже дать доступ роли модератора без остальной админки. Код — [imageModerationService.ts](../backend/src/services/imageModerationService.ts), тесты — [moderation.test.ts](../backend/test/moderation.test.ts).

Попутно исправлено: «Проверить» в карточке «ИИ-провайдер» падал с «input messages must contain the word 'json'» — OpenAI требует слово JSON в самом сообщении, а не только в инструкциях. Теперь `completeJson` добавляет его сам, если в тексте его нет.
